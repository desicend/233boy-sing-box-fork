# Snell v5 Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add native Snell v5 inbound management to the existing script without changing the behavior or JSON format of other protocols.

**Architecture:** Extend the existing `add`, `get`, `create`, `info`, `change`, and `url_qr` case flows with a dedicated Snell state path. Keep `src/core.sh` as the runtime baseline and apply the same Snell-specific behavior to root `core.sh` without overwriting their unrelated differences. Use a deterministic, offline fake core in a test matrix that sources both scripts.

**Tech Stack:** Bash, `jq`, OpenSSL random generation, `sing-box check`, shell integration tests.

**Spec:** `docs/superpowers/specs/2026-09-07-snell-support-design.md`

## Global Constraints

- Require `sing-box >= 1.14.0`; reject empty, `unknown`, and unparseable versions.
- MVP supports Snell v5 only; reject every other Snell version.
- MVP accepts `obfs_mode` values `none` and `http` only; default is `none`.
- Generate a non-empty PSK independently from UUID generation; never use UUID as the default PSK.
- Generate only `type`, `tag`, `listen`, `listen_port`, `version`, `psk`, and `obfs_mode` for a Snell inbound; do not add `tls`, `reality`, or `transport`.
- Reject ports outside `1-65535` and ports used by an active listener or saved node JSON, excluding the current node during its own port change.
- Validate every Snell create/change candidate with `sing-box check -c <temporary-file>` before replacing the existing JSON.
- On validation failure, leave the old JSON, metadata, and service state untouched.
- `url` and `qr` must never emit or encode a `snell://` URL; both use the exact parameter-import guidance.
- Apply Snell behavior to both `core.sh` and `src/core.sh`; preserve unrelated differences between those files.
- New automated tests must be offline and deterministic; real-client interoperability remains manual acceptance.

## Interfaces Between Tasks

The implementation uses these shell variables and functions across the tasks:

- `snell_version`: numeric Snell version, default `5`, validated by `snell_version_valid`.
- `snell_psk`: non-empty PSK, generated by `get_snell_psk` when omitted.
- `snell_obfs_mode`: `none` or `http`, default `none`, validated by `snell_obfs_mode_valid`.
- `require_snell_support`: exits through `err` unless `is_core_ver` is `1.14.0` or newer.
- `snell_config_port_used <port> [current-config]`: returns success when another saved node JSON uses `<port>`.
- `validate_snell`: validates the current `port`, `snell_psk`, `snell_version`, and `snell_obfs_mode` before JSON generation.
- `create server Snell`: writes and checks a temporary Snell JSON, then atomically installs it.

- [ ] **Step 3: Add Snell state, validation, and protocol dispatch to both core scripts.**

In both files, append `Snell` to `protocol_list`. Add these helpers after `get_uuid`:

```bash
get_snell_psk() {
    local psk
    psk=$(openssl rand -base64 32 2>/dev/null | tr -d '\n') || return 1
    [[ $psk ]] || return 1
    printf '%s\n' "$psk"
}

snell_version_valid() {
    [[ $1 == 5 ]]
}

snell_obfs_mode_valid() {
    [[ $1 == none || $1 == http ]]
}

require_snell_support() {
    local version=${is_core_ver#v} major minor
    [[ $version =~ ^([0-9]+)\.([0-9]+) ]] || err "无法确认当前 sing-box 版本 ($is_core_ver), Snell 需要 sing-box 1.14.0 或更高版本."
    major=${BASH_REMATCH[1]}
    minor=${BASH_REMATCH[2]}
    ((major > 1 || major == 1 && minor >= 14)) || err "当前 sing-box 版本 ($is_core_ver) 不支持 Snell, 请先升级 sing-box core 到 1.14.0 或更高版本."
}

snell_config_port_used() {
    local wanted=$1 current=${2:-} file
    shopt -s nullglob
    for file in "$is_conf_dir"/*.json; do
        [[ ${file##*/} == "$current" ]] && continue
        jq -e --argjson port "$wanted" 'any(.inbounds[]?.listen_port?; . == $port)' "$file" >/dev/null 2>&1 && {
            shopt -u nullglob
            return 0
        }
    done
    shopt -u nullglob
    return 1
}

validate_snell() {
    local current_port
    require_snell_support
    [[ $(is_test port "$port") ]] || err "($port) 不是一个有效的端口. $is_err_tips"
    current_port=$(jq -r '.inbounds[0].listen_port // empty' "$is_conf_dir/${is_config_file:-missing}" 2>/dev/null)
    if [[ $port != "$current_port" ]] && [[ $(is_test port_used "$port") ]]; then
        err "无法使用 ($port) 端口. $is_err_tips"
    fi
    snell_config_port_used "$port" "${is_config_file:-}" && err "无法使用 ($port) 端口. $is_err_tips"
    [[ $snell_psk ]] || err "Snell PSK 不能为空. $is_err_tips"
    snell_version_valid "$snell_version" || err "Snell 版本目前只支持 5. $is_err_tips"
    snell_obfs_mode_valid "$snell_obfs_mode" || err "Snell 混淆模式只支持 none 或 http. $is_err_tips"
}
```

Add a `snell)` branch to `add()` that sets `is_use_port=$2`, `is_use_pass=$3`, `is_use_version=$4`, and `is_add_opts="[port] [psk] [version]"`. Map `snell` to `is_new_protocol=Snell` before this case. Include `is_use_version` in the `auto` argument cleanup. For Snell, assign `snell_psk=$is_use_pass` rather than assigning `password` or `ss_password`; assign `snell_version=$is_use_version` when supplied. Before creation, fill `port` with `get_port` if missing, fill `snell_psk` with `get_snell_psk` if missing, set `snell_version=5` and `snell_obfs_mode=none` when unset, then call `validate_snell`.

Add `snell*)` to `get protocol`:

    is_protocol=snell

    [[ $snell_obfs_mode ]] || snell_obfs_mode=none

In `create server`, use `snell-${port}.json` as `is_config_name` for Snell. Build the JSON with `jq -n` and `--arg`/`--argjson` so credentials are data. Write it into a same-directory temporary file, run `"$is_core_bin" check -c "$is_snell_tmp_file"`, remove the temporary file and call `err` on failure, and remove the temporary file before returning from `is_test_json` or `is_gen`.
